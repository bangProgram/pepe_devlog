한손공부 (HanGong)

한 손으로 자투리 시간에 외우는 플래시카드 학습 앱

2026.03 ~ 2026.05 (약 3개월) 커밋 39 1인 개발 (기획·개발·출시)

🎯 문제 정의

영어 단어 암기 앱은 많지만, 출퇴근·대기 같은 자투리 시간에 한 손으로 쓰기엔 불편한 앱이 대부분이었다.

로그인을 강제하거나, 화면이 무겁거나, 한국 학습자가 정작 많이 찾는 한자·사자성어 콘텐츠는 빈약했다.

그래서 "지하철에서 엄지 하나로, 가입 없이 바로 외운다"를 목표로 삼았다.

💡 솔루션 · 핵심 기능

  • 한 손 스와이프 학습 — 카드를 뒤집고 좌(알아요)/우(몰라요)로 스와이프. 엄지 하나로 끝나는 인터랙션.
  • SRS 간격 반복 — SM-2 변형 알고리즘을 알아요/몰라요 이진 응답으로 단순화. 2연속 정답 시 마스터 처리.
  • 게이미피케이션 — XP·10단계 성장(씨앗→대숲)·스트릭·16개 뱃지로 매일 돌아올 이유를 설계.
  • 영어 + 한자 트랙 — 시험/일상/비즈니스/트렌드 영어에 더해 사자성어·고사성어·천자문·고전명구·한자까지 51개 덱으로 확장.
  • 가입 없이 즉시 학습 — 비로그인은 localStorage 전용, 로그인하면 Supabase로 기기 간 동기화.
  • 오늘의 트렌드 단어 — RSS 뉴스에서 시의성 있는 단어를 수집하는 파이프라인.

🛠 기술 스택

Next.js 14 (App Router · SSG)TypeScriptTailwind CSS ZustandFramer MotionSupabase CapacitorAdMob

🏗 아키텍처 · 주요 결정

Capacitor WebView에서 안정적으로 돌리기 위해 SSG 전용(output: 'export')으로 못박았다. API 라우트도 SSR도 없이 모든 페이지를 정적 생성한다.

저장소는 하이브리드 전략 — 비로그인 사용자는 localStorage만 쓰고, 로그인하면 Supabase로 동기화하되 DB를 우선으로 복원해 기기 교체에도 학습 기록이 살아남게 했다.

웹/네이티브 분기는 플랫폼 브릿지로 추상화해 햅틱·공유·광고를 한 인터페이스로 다뤘다.

🧩 막혔던 점과 해결

  • SSG 제약 안에서 동적 학습 앱 — SSR을 못 쓰니 모든 상태를 클라이언트에서. trailingSlash 라우팅 규칙과 SSR 가드(typeof window 체크 + 하이드레이션 분기)를 전 훅에 일관 적용해 깜빡임·불일치를 잡았다.
  • 이중 저장소 동기화 충돌 — 로컬과 DB가 동시에 존재할 때 무엇을 진실로 볼지. DB 우선 복원 + 로컬 신규 데이터만 병합하는 규칙으로 정리했다.
  • iOS App Store 심사 대비 — Privacy Manifest·ATT·AdMob 연동, 그리고 회원탈퇴 시 Apple refresh token 서버사이드 revoke까지 출시 요건을 맞췄다.
  • 한자 트랙 확장 — 영어 카드와 구조가 다른 한자 카드(유래·출전·글자별 음뜻)를 카드 타입 분기 렌더링과 마이그레이션으로 흡수했다.
  • 릴리스 반복 자동화 — versionCode/versionName 자동 증가 + AAB 빌드를 스크립트(app-bundle-rollup)로 묶어 출시 사이클을 단축했다.

📈 결과 · 배운 점

3개월간 39커밋으로 Play Store 프로덕션 출시(v1.0.x)까지 도달했고, 영어 단어 앱으로 시작해 한자 트랙까지 51개 덱으로 확장했다(iOS 출시 준비 중).

"정적 사이트 + 네이티브 래핑"이라는 제약이 오히려 구조를 단순하게 유지시켜줬고, 오프라인 우선·로그인 선택이라는 결정이 첫 학습까지의 마찰을 크게 줄였다.

가장 큰 교훈은 출시는 기능이 아니라 요건(심사·정책·서명·자동화)의 싸움이라는 것.
