목차

    왜 만들었나

    저는 출퇴근길이나 잠깐 비는 시간에 단어를 외우고 싶었는데, 막상 쓰려니 손에 맞는 앱이 잘 없었습니다.

    로그인부터 해야 하거나 화면이 무거워서 한 손으로 쓰기 불편한 경우가 많았고, 한국 사람이 많이 찾는 한자·사자성어 콘텐츠는 생각보다 빈약했습니다.

    그래서 "지하철에서 엄지 하나로, 가입 없이 바로 외운다" 정도를 목표로 잡고 만들기 시작했습니다. 처음엔 그냥 제가 쓰려고 만든 앱이었는데, 비슷한 불편을 느끼는 분도 있을 것 같았습니다.

    핵심 기능

    기능은 욕심내지 않고 최대한 단순하게 가져가려고 했습니다.

    • 한 손 스와이프 학습카드를 뒤집고 좌(몰라요)/우(알아요)로 스와이프. 엄지 하나로 끝나는 인터랙션.
    • SRS 간격 반복SM-2 변형 알고리즘을 몰라요/알아요 이진 응답으로 단순화. 2연속 정답 시 마스터 처리.
    • 게이미피케이션XP·10단계 성장(씨앗→대숲)·스트릭·16개 뱃지로 매일 돌아올 이유를 설계.
    • 영어 + 한자 트랙시험/일상/비즈니스/트렌드 영어에 더해 사자성어·고사성어·천자문·고전명구·한자까지 51개 덱으로 확장.
    • 가입 없이 즉시 학습비로그인은 localStorage 전용, 로그인하면 Supabase로 기기 간 동기화.
    • 오늘의 트렌드 단어RSS 뉴스에서 시의성 있는 단어를 수집하는 파이프라인.

    아키텍처 · 주요 결정

    앱을 Capacitor로 감싸서 낼 생각이었기 때문에, WebView 안에서 탈 없이 도는 게 중요했습니다. 그래서 Next.js를 SSR 없이 SSG 전용(output: 'export')으로 고정했습니다. 처음엔 API 라우트를 쓸까 고민했지만, 결국 모든 화면을 정적으로 만들고 상태는 클라이언트에서 처리하는 쪽이 단순했습니다.

    저장소는 조금 고민이 됐습니다. 가입을 강제하고 싶지 않아서 비로그인은 localStorage만 쓰고, 로그인하면 Supabase로 동기화하도록 했습니다. 대신 기기를 바꿔도 기록이 남도록 복원은 DB를 우선으로 뒀습니다.

    웹과 네이티브에서 다르게 동작하는 부분(햅틱·공유·광고)은 플랫폼 브릿지로 한 번 감싸서, 부르는 쪽은 같은 코드로 쓰게 했습니다.

    막혔던 점과 해결

    처음 해보는 앱 개발이라 막힌 곳이 많았습니다. 그중 기억에 남는 것들입니다.

    • SSG 제약 안에서 동적 학습 앱SSR을 못 쓰니 모든 상태를 클라이언트에서 다뤄야 했습니다. trailingSlash 라우팅 규칙과 SSR 가드(typeof window 체크 + 하이드레이션 분기)를 훅마다 일관되게 적용해 깜빡임·불일치를 잡았습니다.
    • 이중 저장소 동기화 충돌로컬과 DB가 동시에 있을 때 무엇을 진실로 볼지가 문제였습니다. DB 우선 복원 + 로컬 신규 데이터만 병합하는 규칙으로 정리했습니다.
    • iOS App Store 심사 대비Privacy Manifest·ATT·AdMob 연동, 회원탈퇴 시 Apple refresh token 서버사이드 revoke까지 출시 요건을 맞췄습니다.
    • 한자 트랙 확장영어 카드와 구조가 다른 한자 카드(유래·출전·글자별 음뜻)를 카드 타입 분기 렌더링과 마이그레이션으로 흡수했습니다.
    • 릴리스 반복 자동화versionCode/versionName 자동 증가와 AAB 빌드를 스크립트로 묶어 출시 사이클을 줄였습니다.

    결과 · 배운 점

    약 3개월 동안 39번 커밋해서 Play Store와 App Store에 모두 정식 출시했습니다. 영어 단어로 시작했지만 한자 트랙까지 붙여서 지금은 51개 덱이 됐습니다.

    만들면서 느낀 건 "정적 사이트 + 네이티브로 감싸기"라는 제약이 오히려 구조를 단순하게 유지하는 데 도움이 됐다는 점입니다. 가입을 선택으로 두고 오프라인을 우선한 것도 첫 학습까지의 문턱을 낮춰줬다고 생각합니다.

    아직 부족한 부분도 많지만, 개인적으로 가장 크게 배운 건 출시는 기능을 다 만드는 것보다 심사·정책·서명·자동화 같은 요건을 맞추는 싸움에 가깝다는 것이었습니다.
